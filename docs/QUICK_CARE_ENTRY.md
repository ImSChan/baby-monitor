# 마지막 수면·식사 빠른 입력

최신 UI는 CARE_DIALOG_WORKSPACE.md 참고: 별도 육아 기록 탭을 제거하고 드래그/기록 관리/아이·설정을 이 창으로 통합했다.

홈의 기존 육아 기록 참고 안내를 **육아기록으로 더 정확하게 판단하기** 버튼으로 바꿨다. 분석 결과가 없어도 표시한다. 버튼을 누르면 한 창에서 마지막 수면의 잠든/깬 시각과 마지막 식사의 종류/시각을 입력한다. 아는 항목 하나만 저장해도 되고, 식사는 방금 먹었어요 버튼을 지원한다. 날짜도 선택하므로 전날부터 잔 구간을 입력할 수 있다.

기존 POST /api/care/records를 재사용한다. 실제 DB와 월령별 판단 경로로 저장되며 다음 분석부터 참고한다. 별도 DB 변경은 없다. 과거 분석은 재계산하지 않는다. 참고 토글이 꺼져 있거나 월령이 없으면 현재 설정을 바꾸지 않고 필요한 입력/설정 경로를 안내한다. 기존 분석의 근거는 이번 분석에 참고한 기록에서 펼쳐 볼 수 있다.

수면과 식사는 별개의 기존 API 요청이다. 하나가 저장된 뒤 나머지가 실패하면 성공한 항목을 잠그고 실패 항목만 재시도한다. 동일 입력의 재전송은 동일 UUID를 써서 중복 저장을 방지한다. 계정이 변경되면 추가 저장을 중단하고 창을 다시 열도록 한다. 중복 수면은 서버의 기존 409/소유권 검증으로 막는다.

변경 파일: components/care/QuickCareDialog.jsx 및 테스트, CareContextNote.jsx, components/home/BabyStatusOverview.jsx, Android app/build.gradle(v1.10, versionCode 11).

검증: 프런트엔드 23개 파일/93개 테스트 통과. 빠른 입력 신규 6개 테스트는 두 항목/단일 항목 저장, 입력 누락, 일부 실패 후 재시도와 UUID 유지, 계정 변경, 비활성 설정 보존을 확인한다. 실제 로컬 Edge(390×844)에서 분석 없는 홈 → 버튼 → 수면/식사 입력 → 실제 API 저장 → GET 조회로 두 레코드 확인, 가로 넘침 없음. 임시 SQLite만 사용했으며 운영 데이터/푸시에는 접근하지 않았다.

배포: 이전 회원가입/월령 기능의 007과 새 API가 적용된 환경이면 이번 변경을 위한 추가 DB 작업이나 백엔드 재배포는 없다. GitHub main 연동 Vercel 배포를 확인한다. 내장 웹 자산을 사용하는 Android는 npm.cmd run build -- --mode android, npx.cmd cap sync android 후 Android Studio에서 다시 실행하거나 v1.10 APK로 갱신한다.

Vite android build / cap sync / Gradle assembleDebug 성공. v1.10 debug APK 생성. 실기기 설치 및 실제 FCM 수신 시험은 이번 변경에서 실행하지 않았다.
