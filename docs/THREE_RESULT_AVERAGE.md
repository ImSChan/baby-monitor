# 최신 3회 연속 상태와 3건 평균 점수

홈 대표 상태는 가장 최근의 동일 상태 3회 연속 분석 구간을 사용한다. 같은 상태가 4회 이상이면 가장 최근 3건으로 이동하며, 새 상태가 1~2회만 나오면 이전 확정 구간을 유지한다. 계정과 카메라별로 분리하고 안정 상태도 포함한다. 오래된 구간도 제외하지 않는다.

GET /api/emotions/representative가 기존 latest_confirmed_event 조회를 재사용하고, 해당 결과까지 같은 카메라의 정확한 마지막 3개 행을 가져온다. 각 상태를 need/분류명으로 맞춰 동일한 상태의 점수끼리 평균한다. 순위 칸(매번 2순위/3순위)끼리 합치지 않는다. 대표 상태 점수도 3건 평균이다. 남은 상태 중 3개 점수가 모두 기록된 상태를 평균 내림차순으로 정렬해 2·3순위로 표시한다. 평균은 6자리로 계산하고 UI는 기존 정수 % 반올림을 사용한다.

예: 배고픔 .90/.80/.70 → .80(80%), 불편함 .02/.35/.10 → .156667(16%), 졸림 .08/.05/.20 → .11(11%). 마지막 한 건에서는 졸림20%가 불편함10%보다 크지만 평균은 불편함이 2순위다.

저장되지 않은 후보 값은 0으로 간주하거나 평균 분모를 줄이지 않는다. 세 건 모두에 있는 실제 값만 평균에 포함하고 없는 순위는 기록 없음으로 표시한다. 실제 0점이 세 건에 있으면 0으로 평균한다. sampleIds/sampleCount/scoreBasis/candidateCoverage를 반환해 근거를 확인할 수 있다. 시각·육아 기록 참고 내역은 구간의 마지막 분석 기준이다. 원본 분석·피드백·학습 정답/가중치를 수정하지 않는다. dashboard.confirmedEmotion도 같은 집계 응답을 사용한다.

## 이전 서버 호환

새 endpoint가 404인 경우 기존 최근 분석 이력 API에서 실제 연속 3건을 찾고 동일한 평균을 계산한다. 최근 이력에 3건이 없으면 기존 최신 상태 알림의 분류만 유지하고 평균 확인 중으로 표시한다. 단일 알림 점수를 3건 평균으로 표시하지 않는다. 오래된 전체 기록까지 정확히 찾으려면 새 API를 적용해야 한다. 네트워크/인증 실패를 404처럼 숨기지 않는다.

## 변경 파일

- confirmed_state_service.py: 최신 연속 3건의 상태별 평균, 원본 보존, coverage.
- routers/emotions.py: 인증된 representative 읽기 API, dashboard.py: 동일 집계 적용.
- representativeState.js/representativeApi.js: 기존 서버 호환과 실제 이력 평균.
- HomePage.jsx/BabyStatusOverview.jsx: 평균 데이터 사용 및 표기.
- 서버/클라이언트 집계·API·화면 테스트, review_demo.py의 모의 점수 파라미터.
- Android v1.20/versionCode21. 모델/Worker 추론 코드·DB 스키마는 이번에 변경하지 않았다.
