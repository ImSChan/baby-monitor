# 육아 기록 탭을 홈 입력 창으로 통합

하단 육아 기록 탭과 CarePage를 제거했다. 하단은 홈/라이브 2개다. 알림은 홈 상단 종 아이콘, 설정은 그 오른쪽의 톱니바퀴로 접근한다. 미확인 알림이 있으면 종 아이콘에 빨간 점을 표시한다. 홈의 육아기록으로 더 정확하게 판단하기에서 기존 기록 UI를 이용한다. 분석이 없어도 버튼은 표시한다.

- 시간 입력: 마지막 수면의 깬 날짜, 손가락 드래그, 5분 슬라이더, 자정 넘김, 정확한 시각 직접 입력. 미리보기 수면은 선택하기 전 저장하지 않으며 드래그/슬라이더 조절 또는 이 수면 구간 기록 체크로 선택한다. 식사는 이유식·식사/수유/간식 버튼과 먹은 시각, 방금 먹었어요를 지원한다. 두 항목 또는 아는 한 항목만 저장한다.
- 최근 기록: 최근 7일 목록, 식사/기상 및 기록된 24시간 수면 요약, 수정·삭제. 수정은 같은 창 안에 표시하며 새 dialog를 중첩하지 않는다. 기존 revision 충돌 및 수면 중복 방지 API를 유지한다.
- 아이·설정: 아이 이름·월령 수정, AI 참고 켜기/끄기, 월령별 참고 기준과 출처. 기록 변경 후 입력 창의 요약도 갱신한다.

창 상단 제목·내부 메뉴는 스크롤 중에도 유지한다. 설정의 프로필 관리는 /?care=settings로, 기존 /care 주소는 /?care=history로 연결한다. 과거 링크도 빈 화면/삭제된 탭으로 보내지 않는다. URL로 열린 창을 닫으면 care 매개변수만 제거하고 다른 매개변수는 보존한다.

API/DB/분석·학습 정책은 변경하지 않았다. 기존 사용자 기록도 삭제하지 않았다. 이전 회원가입·월령 기능의 007 마이그레이션/API가 적용돼 있다면 이번 변경에 추가 DB 작업이나 백엔드 재배포는 없다. Vercel main 배포를 확인하고 내장 자산 Android는 새 v1.11/versionCode12 APK 또는 재빌드가 필요하다. 운영 자동 재배포는 수행하지 않는다.

주요 파일: BottomNav.jsx(탭 제거), AppRouter.jsx(이전 주소 연결), CareContextNote.jsx(내부 메뉴 딥링크), QuickCareDialog.jsx(드래그·종류 버튼·메뉴), CareManagement.jsx(이전 CarePage의 기록/프로필/설정 이동), 기존 CarePage.jsx 삭제, SettingsPage/RegisterPage 안내 갱신. 사용자 데이터나 API는 삭제하지 않았다.

검증 결과는 최종 시험 후 아래에 기록한다.

- 프런트엔드: 24개 파일/95개 테스트 통과. 탭 4개, 드래그 선택·선택 해제, 저장/부분 실패 재시도, 계정 변경, 과거 링크 진입·닫기, 수정 revision, 삭제, 프로필 수정, 참고 설정 실패 시 복구를 확인했다.
- 실제 로컬 Edge 390×844 + 임시 SQLite: 손가락 동작에 대응하는 pointer drag → 수면/수유 2개 저장 → 이전 /care 링크 이동 → 식사 수정 revision 2 → 삭제 → 월령 14로 수정 → 참고 끄기 → 설정의 프로필 관리 진입. 단일 dialog, 가로 넘침 없음. 실제 운영 계정/DB/FCM은 사용하지 않았다.
- Vite android build 통과. 새 APK 빌드 결과는 아래 기록한다.
- Capacitor sync / Gradle assembleDebug 성공. v1.11/versionCode12 debug APK 생성. 실제 Android 기기 설치·FCM 수신은 미실행이다.
