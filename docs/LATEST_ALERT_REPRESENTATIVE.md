# 대표 상태를 가장 최근 상태 알림으로 표시

홈 대표 상태는 기존 GET /api/push/events 목록에서 가장 최근 상태 알림의 result를 사용한다. 별도의 3회 연속 판정 계산이나 새 dashboard.confirmedEmotion 필드를 요구하지 않는다. 이 필드가 없는 기존 서버에서도 알림 목록이 조회되면 표시할 수 있다.

- 서버 알림 목록 순서대로 가장 최근 상태 알림을 선택한다. kind=review 정기 돌아보기 알림은 건너뛴다.
- 알림의 경과 시간, readAt, 발송/만료 상태로 제외하지 않는다. 오래되거나 읽은 알림도 최근 상태 알림이면 계속 표시한다.
- 최근 페이지에 돌아보기 알림만 있으면 100개 단위로 과거 페이지도 조회한다. 임의 날짜/최근 20개 제한을 두지 않는다. 취소된 계정 요청은 중단한다.
- 상태·점수·2/3순위·시각은 같은 알림 snapshot을 사용한다. 점수가 없으면 점수 없음, 후보가 없으면 기록 없음을 표시한다. 최근 분석 결과로 대신 채우지 않는다.
- 분석 시각은 알림 result의 createdAt/created_at을 우선하고 없으면 알림 생성 시각을 쓴다. 아래 버튼은 해당 알림 상세로 연결한다. 대표 상태를 읽는 것만으로 알림을 읽음 처리하지 않는다.
- 알림이 없으면 아직 상태 알림이 없어요, 조회 실패면 불러오기 실패를 구분한다. 알림 수신/읽음 이벤트, 15초 갱신, 화면 복귀로 업데이트한다.

변경 파일: api/notificationApi.js(추가), HomePage.jsx, BabyStatusOverview.jsx 및 테스트, Android build.gradle(v1.18/versionCode19). 기존 backend/API/Worker/DB는 변경하지 않았다. 이전 CONFIRMED_STATE_OVERVIEW의 대표 상태 계산/새 API 적용 요건은 이번 홈 표시 방식에는 적용되지 않는다.

검증: 프런트엔드 29개 파일/132개 테스트 통과. 오래된 읽은·만료 알림, 확인 필드가 없는 구형 알림, 새 돌아보기 제외, 100개 넘는 과거 목록 조회, 같은 알림의 점수/시각 유지, 요청 취소/오류, 최신 분석이 대표 알림을 덮어쓰지 않는 경우를 확인했다.

실제 Edge 390×844와 loopback 임시 SQLite에서 불편함 알림을 생성하고 읽음 처리했다. 응답 시각을 2024-01-01로 바꿔 표시를 확인했으며 dashboard 요청은 503으로 차단하도록 구성했다. 실제 홈의 dashboard 요청은 0회, 불편함 87%와 후보 2·3순위 정상 표시, 해당 알림 링크 정상, 가로 넘침 없음. 운영 계정/데이터/실제 FCM에는 접근하지 않았다.

Vite android build / cap sync / Gradle assembleDebug 성공. Android v1.18 debug APK 생성. 실제 실기기 설치는 미실행이다. DB 마이그레이션/배포 PC API·Worker 갱신은 이번 수정에 필요하지 않다. Vercel main 배포를 확인하고 내장 자산 앱은 새 APK 설치 또는 최신 소스 build/sync 후 실행한다. 운영 자동 재배포는 하지 않았다.
