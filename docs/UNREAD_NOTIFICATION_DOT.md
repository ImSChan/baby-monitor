# 알림 진입과 새 알림 표시

하단 알림 탭을 제거해 홈/라이브 2개만 남겼다. 기존 상단 종 아이콘으로 알림 목록과 설정에 접근한다. 서버의 미확인 개수(unreadCount)가 1 이상이면 종 오른쪽 위에 빨간 원을 표시하며 접근성 이름은 알림 (새 알림 있음)이다. 목록을 열기만 했다고 숨기지 않고 모든 알림을 확인하면 사라진다.

기존 인증된 GET /api/push/events?limit=1&offset=0을 재사용한다. 로그인 직후, native 푸시 수신·클릭, 읽음 저장 이벤트, 창 포커스/foreground 복귀에 갱신하며 화면이 보이는 동안 30초마다 조회한다. 알림 설정이 꺼져 있어도 이미 받은 미확인 알림은 표시한다. 푸시 전송·이메일·DB 변경은 없다.

응답은 계정 ID와 요청 순서로 검사하고 이전 요청은 취소한다. 계정 변경/로그아웃 시 이전 계정의 빨간 점을 즉시 감춘다. 일시적 조회 실패는 마지막으로 확인한 개수를 유지하고 이후 갱신에서 재시도한다.

검증: 프런트엔드 24개 파일/100개 테스트 통과. 서버 개수 표시·해제, native 수신 갱신, 계정 전환·로그아웃의 늦은 응답, 30초 갱신, 실패 후 포커스 복귀를 검증했다. 실제 Edge 390×844와 임시 SQLite에서 mock 분석 이벤트로 알림 2개를 생성하고 실제 UI의 확인 완료 버튼을 사용해 2→1→0을 확인했다. 모두 읽으면 홈의 빨간 점이 사라지고 하단은 홈/라이브만 표시됐다. 실제 운영 FCM은 보내지 않았다.

Vite android build / Capacitor sync / Gradle assembleDebug 성공. Android v1.13/versionCode14. 실기기 설치/실제 FCM 수신은 이번 시험에서 실행하지 않았다. DB 마이그레이션/백엔드 갱신은 필요하지 않다. main 연동 Vercel 배포와 내장 자산 Android APK 갱신을 확인한다.
