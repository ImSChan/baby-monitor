# BabyEye 개발 PC 로컬 부하 시험 결과

시험일: 2026년 11월 18일 13:09:59–13:12:19 KST (측정 구간, 준비 시간 제외)

## 결론
측정 요청 10,712건의 예상 밖 응답/네트워크 오류는 0건입니다. 20 VU 60초 지속 시험에서 초당 96.17건, p95 445.09ms였습니다. 50 VU에서는 초당 87.19건, p95 1,348.62ms로 지연이 늘고 처리량이 감소했습니다. 이 조건에서는 고동시성에서의 병목 점검이 필요하지만 운영 서버 한계나 원인이 확인된 것은 아닙니다.

## 환경과 범위
- Windows 개발 PC, 논리 CPU 16개, RAM 약 31.9GiB, Python 3.10.0, 실제 FastAPI/Uvicorn 1프로세스.
- 부하 생성기와 API가 같은 PC에서 실행됩니다. 임시 SQLite DB, 가상 계정 8개, 계정당 분석 240개(총 1,920개)와 가상 알림·피드백을 사용했습니다.
- 실제 라우터/인증/소유권/피드백 저장과 WebSocket 인증·heartbeat를 사용했습니다. 브라우저 UI를 조작하는 프런트엔드 렌더링 시험은 아닙니다.
- 조회 루프는 요청 완료 후 30ms, 로그인 루프는 100ms 대기하는 closed-loop 방식입니다. VU는 실제 앱 사용자 수나 초당 고정 도착률과 같지 않습니다.
- 운영 API/DB/토큰/가중치를 사용하지 않았고 외부 FCM·GPU 추론/학습·실제 영상 비트레이트·Redis 부하는 시험하지 않았습니다.

| 조회 | 1 | 216 | 21.57 | 12.89 | 0 |
| 조회 | 5 | 1164 | 115.85 | 40 | 0 |
| 조회 | 20 | 1008 | 99.19 | 428.36 | 0 |

조회 대상은 dashboard, emotions/history, push/events, reviews, training/status, training/analysis-status, live/sessions입니다. 로그인 단계는 실제 Argon2 비밀번호 검증을 수행했습니다. 위 오류 집계는 측정한 부하 요청 기준이며 사전 준비·자원 조회·예상된 계정 간 404 검사는 별도로 처리했습니다.

## 저장과 세션 무결성
- 8개 계정에서 각각 12회 상태 피드백 변경: 저장 96회, 새 ReviewAction 96개로 일치.
- 최초 저장 요청 재전송 8회 모두 원래 응답과 일치하고 중복 action이 없었습니다. 같은 계정의 동일 요청을 동시에 경합시키는 PostgreSQL 잠금 시험을 대신하지 않습니다.
- 최종 피드백 144개와 request_id 고유 수 144개가 일치했습니다. 다른 계정 알림 피드백 조회는 404였습니다.
- 20개 세션/40개 WebSocket과 조회 20 VU를 병행했습니다. heartbeat pong 400회, 오류 0회, 종료 후 잔여 세션 0개였습니다. 실제 P2P 미디어 전송 용량 시험은 아닙니다.

## 메모리 관측
Windows API로 서버 프로세스의 단계별 RSS와 프로세스 최대 RSS를 읽었습니다. 초기 약 76.0MiB, 최종 약 97.4MiB, 실행 중 최대 약 477.5MiB였습니다. 20 VU 지속 조회 종료 RSS는 약 83.6MiB였습니다. 비밀번호 검증 동시 실행 등 단계가 서로 다르므로 최대치를 정상 상태 상주 메모리와 동일하게 해석하면 안 됩니다. 짧은 실행의 시작/종료 차이만으로 누수 유무를 확정할 수 없습니다.
이번 개발 PC 시험은 디스크 IOPS/지연과 Docker/WSL2 메모리의 연속 계측을 포함하지 않습니다. 배포 PC 프롬프트에서 추가 측정합니다.

## 제외와 후속 확인
- SQLite 결과는 PostgreSQL의 잠금, 커넥션 풀, 쓰기 경합, 운영 데이터 규모의 결과로 일반화할 수 없습니다.
- 단일 PC의 부하 생성기 CPU/이벤트 루프/서버 스레드/DB가 함께 영향을 받습니다. 50 VU 지연 원인은 이 측정만으로 확정할 수 없습니다.
- 장시간 누수, 24시간 운영, Android 잠금/절전, 인증 60분 경계, 외부망/TURN 및 실제 FCM 전달은 별도 시험입니다.
- 운영 SLA가 정해지지 않았으므로 0오류라는 기능 결과와 성능 적합성을 구분합니다. p95 1초를 임시 참고선으로 보면 50 VU 단계는 이를 초과했습니다.

## 재현
backend에서 테스트 의존성을 갖춘 Python으로 실행합니다.

    python tools/local_load_test.py --output <결과폴더> --seconds 10 --hold 60

원격 대상 URL을 받지 않으며 직접 생성한 루프백 fixture 식별자를 확인합니다. 테스트용 DB/자료는 임시 폴더에 만들고 종료 시 정리합니다. 생성한 프로세스만 종료하며 운영 서비스나 볼륨을 재시작/삭제하지 않습니다. 결과는 results.json, server.log로 저장하고 JWT/비밀번호 응답은 보고서에 저장하지 않습니다.

## 예비 실행 처리
