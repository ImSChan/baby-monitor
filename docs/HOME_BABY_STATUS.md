# 홈 화면: 아기 상태 중심으로 통합

## 구성

기존 감정 화면의 상태 후보·분석 분포·최근 기록을 홈으로 통합하고 사용자에게 보이는 이름을 ‘아기 상태’로 바꿨다. 감정 탭은 제거하며 기존 /emotion 주소는 홈으로 redirect한다. 피드백 화면의 돌아가기 링크도 홈으로 연결한다. 하단 메뉴는 홈 / 라이브 / 알림 / 설정 4개다.

홈의 표시 순서는 다음과 같다.

1. 최근 AI 분석: 아이의 요구/상태와 안내 문구, 분석 시각, 예측 후보 최대 2개, 실제 상태 피드백 링크.
2. 최근 분석 흐름: 기존 API의 최근 최대 20건 기준 상태별 횟수와 분포 막대. 최근 4건을 먼저 보여주고 전체 기록을 펼친다. 당일 전체 통계나 실제 상태의 확정 비율로 표현하지 않는다.
3. 지난 12시간 돌아보기: 알림 사건을 모아서 응답하는 기존 화면으로 연결.
4. 직접 모습 확인하기: 홈캠 연결 가능 여부와 라이브 보기/홈캠 시작 링크.
5. 영상으로 분석하기: 기존 업로드·분석을 유지하고 완료 결과는 맨 위 요약에 합친다.

## 데이터·동작

- ‘현재 아기가 우는 이유’처럼 울음을 전제하던 문구를 제거했다. feeding/sleep/care/stable 및 기존 한글·영문 라벨을 배고픔/졸림/돌봄 필요/편안함으로 표시한다. 최종 need가 있으면 우선 사용한다.
- 예측 점수와 과거 기록임을 표시하며 15분 이상 지난 결과는 ‘이전 분석 기록’으로 구분한다. 서버의 기존 naive 시간은 KST로 해석한 뒤 기기 현지 시각으로 표시한다.
- dashboard·최근 기록·이번 업로드의 분석 시각을 비교해 최신 결과를 사용한다. 원본 점수/라벨/DB 데이터는 변경하지 않는다.
- 홈에서는 WebRTC 시청 소켓/미디어를 만들지 않는다. 실제 시청은 기존 라이브 화면에서 수행하므로 홈 방문만으로 viewer 슬롯을 차지하지 않는다.
- 라이브 연결 여부와 무관하게 화면이 보일 때 15초마다 분석을 갱신하며 화면 복귀/알림 변화 때도 갱신한다. API 응답은 각각 독립적으로 반영하여 느린 라이브 서버가 상태 요약을 막지 않는다. 각 응답의 대기는 10초로 제한한다.
- 새로고침/이탈/계정 변경 시 요청을 취소하고 이전 계정 응답을 무시한다. 업로드는 기존 소유권·인증·취소 경로를 유지한다.
- 최초 기록이 없는 경우, 서버 조회 실패, 오래된 기록을 서로 구분한다. 일부 API 오류가 전체 화면을 가리지 않는다.

백엔드 라우트/DB schema/학습 로직은 변경하지 않았다. 기존 /api/emotions/* 및 emotion 필드 이름도 호환성을 위해 유지한다. 이번 변경 자체에 새 migration이나 API/Worker 재시작은 필요 없다. 앞선 스마트홈 제거의 005 적용은 별도의 기존 작업이다.

## 검증

- 전체 프런트엔드 56 passed / 14 files. 상단 요약→기록→라이브 순서, 빈 기록/서버 오류 구분, 라이브 요청 지연에도 분석 표시, 시청 중이 아니어도 갱신, 계정 전환 시 늦은 응답 차단, 이탈 후 늦은 업로드 전송 차단을 검증했다.
- 실제 Edge 브라우저의 mock API로 390×844 및 너비 320 화면을 검증했다. 데이터 있음/없음/오래됨/서버 오류, 20건 기록 펼치기, 구주소 redirect, 메뉴 4개, 가로 넘침 없음, JS page error 0 확인. 실제 운영 API/아기 데이터는 사용하지 않았다.
- Android 모드 Vite build, Capacitor sync, JDK21 assembleDebug 성공. v1.5 / versionCode6. 실제 단말 설치·실행은 하지 않았다.
- 백엔드 소스 변경이 없어 이번 작업에서는 백엔드 테스트를 반복하지 않았다.

## 적용

main push 후 기존 Vercel 배포를 확인한다. 원격 웹을 로드하는 앱은 새 웹 화면을 로드하고, 로컬 assets형 Capacitor 앱은 v1.5 APK를 설치한다. 캐시 삭제만으로 로컬 assets가 갱신되지는 않는다. APK 서명이 다르면 기존 서명키로 재빌드하고 앱을 임의 삭제하지 않는다. 서버·DB·GPU 학습에는 이 UI 변경을 이유로 추가 작업하지 않는다.

재현용 브라우저 검증은 저장소 root에서 실행한다. 개발 서버는 별도 터미널에서 babyeye-web 디렉터리의 VITE_API_BASE_URL=http://127.0.0.1:8793 설정으로 npm.cmd run dev -- --host 127.0.0.1 --port 5180 --strictPort를 실행한다. 기존 work/review-browser에 설치한 Playwright와 Edge를 사용해 node babyeye-web/tests/home-browser.mjs를 실행한다. 실제 API 요청은 mock으로 대체하며 결과와 캡처는 ignored work/home-preview에 저장한다.
